## Correctness decisions

- Spotify export `ts` denotes **stream end**. Session intervals are inferred as
  `[ts - ms_played, ts]`, sorted by inferred start and streamed from a cursor.
  Sessions split at breaks greater than 30 minutes. Their listening time is a sum,
  separate from elapsed span; overlapping devices are not silently collapsed.
- A raw event is not automatically a meaningful listen. Meaningful means at least
  30,000 ms. Completion uses known track duration and a 90% threshold; averages cap
  each contribution at 100%. Unknown duration stays unknown. The export alone does
  not supply catalogue duration, so the current normal import usually has no completion metric.
- Discoveries describe the earliest **imported** record, not proof of first-ever exposure.
  Rediscoveries require 90 days between the first record in the selected interval
  and the preceding record. Repeat highlights require at least 10 events, a non-zero
  baseline and at least twice the preceding count. Forgotten tracks require 10 prior
  events and no record in the selected interval. Comparisons use an equal-duration
  preceding interval; no percentage is invented for a zero baseline.
- Calendar bounds respect the device time zone and DST. Detail years now match the
  local calendar. Raw timestamps stay UTC epoch milliseconds. All-time comparisons
  have no finite preceding interval and therefore omit trends/repeat comparisons.
- FTS4 is used with Room 2.x/platform SQLite to preserve Android 7/API 24 compatibility.
  User input becomes bounded, quoted Unicode prefix terms. FTS operators cannot be
  injected. Search includes related songs/albums when an artist matches.
- Backup v1 stores only five normalized source tables, not tokens, raw exports or
  arbitrary schema/SQL. Search indexes are reconstructed through Room triggers.
  The entire ZIP is validated in private temporary storage before replacement.
  FK/uniqueness checks, format version, column allowlists, value checks and a 1 GiB
  decompression budget apply. Failure rolls back; staging files are removed.
- Import, backup, restore and deletion share a process-wide operation mutex. A
  database transaction serializes snapshots with writes. Deletion removes cached
  recap images too; exported copies are outside the app's deletion scope.

## Verification

CI runs domain tests, real Room tests under Robolectric, parser/import integration,
search-input tests, backup round trips and rejection tests, real Hilt/Compose navigation,
Android lint and debug APK assembly. The editing environment cannot download Gradle,
so Android build results come from GitHub Actions, not a claimed local build.

A separate `python scripts/benchmark_sql.py --events 300000` exercises production SQL
against synthetic records (2,000 songs, 100 artists, 400 albums). Initial desktop timings
were 0.001–0.269 seconds per query. These are **not Android latency or importer timings**.
Use a physical mid-range device to decide whether aggregate caches are needed; no
unmeasured claim of instant operation on all devices is made.
